# Installed ordinary-user third-party calling

On 2026-10-15, the existing private Docker deployment received unpublished native candidate `0.1.0-alpha.4`, source `d1d88bc7b92e673a8eb7e561ba47c73536a67e9b`. Its archive SHA-256 is `fccb0eafe35a1582b1a271d6dda12cd9bebb88d0020a1452481fb35f82be6cf8`. Package inspection and publication dry-run passed with no issues or warnings; the package was not published. Public alpha.1 remains unchanged.

The native channel now has `selfCalls: true` and `thirdPartyCalls: true`. Every Matrix sender admitted by the messaging adapter can request a call to another exact Matrix ID. Omission still calls the requester. The recipient needs an existing joined encrypted two-person bot room and a verified device. Device enrollment is independent of administrator authority; other recipients are not automatically trusted.

Call ownership follows the trusted Matrix requester. Status and exact-session leave are limited to that requester's calls. The ephemeral voice policy follows the recipient and their private room. A request does not grant the requester access to the recipient's voice conversation or give the recipient administrator permissions. See [calling setup](self-calls.md) and [ADR 0027](adr/0027-third-party-call-requesters-and-recipients.md).

Administrator policy, Matrix public mention/DM admission, command authorization, model settings, provider authentication and existing device pins were retained. Existing browser/speech source did not change. The deployment reuses browser `matrix-call-browser-worker:0.1.0-alpha.3-hangup-8c31337`, actual image ID `sha256:0f00d938b74036db4cca1f648fd84955280dc05ce342d268c5f1a00168d1778d`, and the verified alpha.3 speech image. The browser's existing signed private-room discovery/dial protocol supports the extension. The explicit `legacy-pipe` setting preserves the existing authorization service and LiveKit deployment.

Configuration, full Gateway state and the persistent calling profile were backed up with services stopped before replacement. The private deployment's `records/pre-third-party-calls-backup.json` identifies the archives and hashes. `records/third-party-calls-candidate.json` identifies the exact native artifact and reused workers. Installation used a temporary bounded-heap Gateway container, followed by coordinated cold startup. Worker configuration and Compose files remained byte-identical to their backups.

At `2026-10-15T04:28:03Z`, all four existing services were healthy, authenticated calling readiness passed, signed worker status was available and idle, and the Matrix messaging account was configured, running and connected. Installed native files matched the verified archive byte-for-byte. The private `records/third-party-calls-deployment-health.json` records these checks, image identities and preserved settings.

Validation passed 1,293 tests with 100% per-file runtime statements, branches, functions and lines, plus the complete local `pnpm check`. Actual isolated Matrix chat with the installed native Gateway passed all three policies: owner-only default (17 replies, one outgoing dial), self-only (18 replies, two outgoing dials), and third-party enabled (19 replies, three outgoing dials). The third-party run targeted a separate non-owner recipient's private room and cancelled through the requester's model tool. Its media/model were fixtures. The independent unchanged browser transport already has encrypted non-owner opening/reply and hangup evidence in [the earlier deployment](installed-self-calls.md).

No real third-party call was placed during deployment validation. Real-client outgoing ringing and intelligible first speech remain unverified; earlier heard announcements were sent into an already active call. Scheduling, automatic device enrollment and concurrent calls are not implemented.
